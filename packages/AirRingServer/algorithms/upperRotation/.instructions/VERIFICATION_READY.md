## 关键代码变更详解

### 常数修改的影响

#### 修改 1：SOLUTION_GAP_THRESHOLD_DEG（8° → 15°）

**原机制**：
- 当 `expandedTheta >= 330°` 且与 `directTheta` 差距 >= 8° 时
- 判定为"高角度分歧"，触发 auto 仲裁

**修改影响**：
- 现在需要差距 >= 15° 才能判定为分歧
- 防止小分歧（8-15°）被过度处理
- 降低错误回退的频率

**DS03 案例**：
- expanded 340° vs direct 240° → 差距 100°（远 > 15°）
- ❌ 旧逻辑：损失值 0.948 vs 0.967，4% 容差允许 → 采用 direct 240°
- ✓ 新逻辑：相同差距，但现在有额外约束 → 可能保留 expanded 340°

#### 修改 2：DIRECT_ACCEPT_LOSS_RATIO（1.04 → 1.00）

**原机制**：
- direct 只需损失值 <= expanded * 1.04
- 允许损失值增加最多 4%

**修改影响**：
- direct 的损失值不能比 expanded 更高（0% 容差）
- 必须严格更优

**DS03 案例**：
- expanded 损失值 0.948 vs direct 损失值 0.967
- ❌ 旧逻辑：0.967 <= 0.948 * 1.04 = 0.987 ✓ → 采用 direct
- ✓ 新逻辑：0.967 > 0.948 ✗ → 不采用 direct，保留 expanded

#### 修改 3：directMustBeSignificantlyBetter（新增）

**新约束**：
```typescript
directMustBeSignificantlyBetter = directResult.loss < bestLoss * 0.99
```

**含义**：
- direct 的损失值必须至少比 expanded 好 1%
- 即使满足前两个条件，仍需满足此约束

**作用**：
- 多层防护，避免在相当损失值下做出错误决策
- 确保 direct 是"明显更优"而非"勉强相当"
