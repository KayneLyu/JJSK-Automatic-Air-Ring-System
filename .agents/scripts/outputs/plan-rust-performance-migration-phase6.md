# Rust 性能迁移阶段 6 计划：受控历史数据观测与联机前预检

## 目标

先建立可重复的受控观测技术预检和人工门禁；本机验收范围根据用户补充调整为 SQLite 历史数据只读回放，不依赖 ADBox/S7，不发送设备指令。完整应用的设备连接风险仍作为部署前约束保留。

## 已知风险

- 完整应用启动会调用设备初始化链路，自动尝试连接 ADBox 和上旋 S7，因此不是只读观测动作。
- 当前 Rust shadow 默认关闭；任何联机观测都必须在单独进程环境中显式设置变量。
- Rust 生产接管仍为 no-go；DS02 与模拟器精度失败继续作为独立阻断项。

## 步骤

1. [x] 只读检查活动进程、shadow 环境变量、Native/Worker 构建产物与默认日志路径。
2. [x] 新增无设备副作用的技术预检脚本，输出机器可读聚合报告。
3. [x] 验证预检脚本在 mise 固定环境下通过，且不会启动 Electron 或连接设备。
4. [x] 形成阶段 6 人工门禁清单，明确现场值守、急停、设备空闲和回滚要求。
5. [x] 修复现场启动前暴露的扫描重建大数组展开栈溢出，并完成回归构建。
6. [x] 用户确认本机验收仅使用历史数据，不在本机执行设备联机观测；部署前现场门禁继续保留。
7. [x] 使用 Electron 运行时对本机 SQLite 历史数据执行一次独立 Rust shadow 回放，生成无原始测点的 telemetry 和聚合报告。
8. [x] 修复只读连接对非 WAL 旧库执行 `journal_mode=WAL` 导致的写入错误，重新构建 Worker 后复测。

## 技术验收标准

- [x] Node 24.18.0、pnpm 10.18.3、Rust 1.88.0 与 `mise.toml` 一致。
- [x] Native addon、Calibration Worker 和主进程构建产物存在。
- [x] 没有正在运行的 AirRing/Electron 进程，没有残留 shadow 环境变量。
- [x] 预检 JSON 不包含原始厚度测点、设备地址、密钥或逐次 telemetry。
- [x] 预检脚本不启动应用、不创建网络连接、不修改部署配置。
- [x] 报告显式标记应用会自动连接设备，真实观测需要现场人工确认。
- [x] 历史观测以只读数据库连接运行，不初始化设备连接，Rust/TypeScript 角度差不超过 `1e-9°`。

## 人工门禁

- [ ] 现场操作人员在场并确认设备处于允许观测的状态。
- [ ] 急停状态和运动区域已人工确认，观测不会触发生产动作。
- [ ] 明确观测窗口、日志路径、停止条件和回滚责任人。
- [ ] 用户再次明确授权启动会自动连接设备的 Electron 应用。
