# Rust 性能迁移 Phase 11 执行计划

## 目标

在 Electron 版本不变时生成仅包含应用内容的 Windows x64 7z，通过兼容性校验和可恢复目录交换更新既有 `win-unpacked`，减少日常构建产物传输量，并保留进入正式发布后的同一分层模型。

## 实施顺序

1. 将 `resources` 定义为不可拆分的内容单元，避免 `app.asar`、Rust addon 与 `better-sqlite3` ABI 产物分离。
2. 新增内容构建脚本：构建 Rust Native，下载 Electron ABI SQLite 预编译，构建前端与主进程，以 electron-builder `dir` 形成权威内容目录并运行无设备自检。
3. 将 `resources`、应用脚本和运行时探针放入暂存目录，生成逐文件 SHA-256 清单，再用通用 7-Zip CLI 归档并执行 `7z t` 完整性检查。
4. 新增 PowerShell 应用脚本：检查进程、调用目标 Electron 运行时探针、校验清单和路径，在安装目录同卷暂存，备份并交换 `resources`，错误时恢复。
5. 对完整基础目录副本执行解压、应用和打包态自检，并构造错误 Electron 版本验证无写入拒绝。
6. 更新部署说明、task plan/context/decisions 与验收输出；正式发布继续增加代码签名和可信渠道门禁，不把普通 SHA-256 当成发布身份认证。

## 风险与回滚

- 运行中覆盖可能遇到文件锁或半更新：脚本检测目标进程并拒绝，目录交换前保留旧内容备份。
- ABI 错配可能使 SQLite 或 Rust addon 无法加载：使用目标 `JJSK.exe` 的真实 Electron/ABI 探针，不依赖人工填写版本。
- 内容包损坏或路径污染：归档测试、逐文件哈希、完整文件集合比对和根路径约束全部通过后才交换。
- 正式渠道被篡改：本阶段提供完整性校验；正式发布前必须在可信流水线签名或发布已签名清单，作为独立门禁。
