# Analysis: 历史上旋角度结果偏差

## 只读验证范围

1. 检查现场 SQLite 的厚度、旋转、换向和扫描脉冲覆盖。
2. 对异常短窗口、两组正常双行程窗口和四行程窗口运行完整 Electron Worker 回放。
3. 分别比较 `auto`、`direct`、`expanded` 目标模式。
4. 对照行程时长、脉冲覆盖、电机频率和算法质量门控定位偏差来源。

## 实测结果

| 窗口 | 特征 | auto | direct | expanded |
| --- | --- | ---: | ---: | ---: |
| 最新两趟 | 2.38min + 10.42min，pulse 0–17000 | 256.43° | 260.00° | 未单独运行（auto 接近该路径） |
| 正常双行程 A | 10.15min + 10.12min，pulse 恒为 0 | 180.00° | 340.32° | 180.00° |
| 正常双行程 B | 10.13min + 10.15min，pulse 恒为 0 | 未运行 | 330.03° | 180.50° |
| 四个正常行程 | 均约 10.13min，pulse 恒为 0 | 未运行 | 310.04° | 未运行 |

## 结论

- 最新选段包含明显时长离群行程，而双行程输入会跳过完整性过滤。
- 正常历史行程没有实际扫描脉冲；expanded 使用时间/信号趋势生成的合成 offset，auto 却把它视为有效位置并选择 expanded。
- auto 的 direct 回退只防高角度分歧，不防 expanded 在 180° 下边界退化。
- direct 也随窗口从 340°、330° 变到四行程 310°，当前数据尚不能形成稳定、可验收的唯一角度。
- 检查区间内 `motorFrequency` 全为 0，`rotation_trip` 为空，换向标记重复，缺少进一步验证运动模型的元数据。
